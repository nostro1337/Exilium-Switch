# Хроника решения кейса: Обход корпоративного DPI и релиз Exilium Switch v1.5.1

Данный документ содержит полную, детальную техническую хронику исследования, локализации проблемы, разработки архитектурного решения, его тестирования и финального релиза в **Exilium Switch v1.5.1**.

---

## 1. Вводные данные и постановка задачи

* **Клиентская среда:** Рабочий ПК сотрудника / системного администратора в корпоративной сети (`aviabasa.local`).
  * Операционная система: Windows 10/11 Enterprise с установленным КриптоПро CSP.
  * Сетевая инфраструктура: локальный шлюз `192.168.12.200`, контроллер домена Active Directory и DNS `192.168.12.223` / `192.168.12.222`.
* **Серверная инфраструктура:** VPS #1 (`89.124.94.246`, Нидерланды, хостинг VDSina).
  * Установлена панель 3X-UI v3.7.0 с ядром Xray v26.7.28.
  * Настроен Inbound `NL-Reality` (порт 443, VLESS Reality с XTLS Vision, маскировка под `dl.google.com`).
  * Обслуживает 5 клиентов: личный ПК (`Nostro-PC`), домашний ноутбук (`Nono-PC`), айфоны семьи и рабочий ПК (`Aviabaza-PC`).
* **Критическое требование пользователя:**  
  *Ни при каких обстоятельствах не нарушить работоспособность сервера для домашнего ПК и мобильных устройств.*
* **Проблема:**  
  При включении туннеля через Exilium Switch на рабочем ПК интернет полностью пропадал, любые внешние запросы зависали на 15–16 секунд и завершались ошибкой:
  ```text
  context deadline exceeded
  curl: (28) Operation timed out after 6005 milliseconds with 0 bytes received
  ```

## 2. Диагностический этап: Сетевая разведка (L3/L4)

Была проведена серия последовательных тестов с рабочего ПК для локализации уровня сбоя (L3 Routing, L4 Firewall или L7 DPI).

| Тест | Команда / Метод | Результат | Вывод |
| :--- | :--- | :--- | :--- |
| **Ping до VPS** | `ping 89.124.94.246` | RTT ~94 мс, 0% потерь | L3-маршрутизация до Нидерландов полностью исправна |
| **TCP Handshake (443)** | PowerShell `Net.Sockets.TcpClient` | `Connected = True` (~90 мс) | Порт 443 наружу открыт, SYN $\to$ SYN-ACK $\to$ ACK проходит |
| **TCP Handshake (2096)** | PowerShell `Net.Sockets.TcpClient` | `Connected = True` (~90 мс) | Порт 2096 наружу открыт |
| **Системный HTTPS (SChannel)** | `curl.exe -I https://ya.ru` / `google.com` | `HTTP/1.1 200 OK` / `302` | Исходящий TLS 1.3 не блокируется глобально |
| **Fallback Reality на сервере** | `curl.exe -k -I https://89.124.94.246/` | `HTTP/1.1 301 Moved Permanently` | Сервер отвечает корректным fallback-сайтом |
| **SNI Fallback Reality** | `curl.exe -k -I --resolve vdsina.ru:443:...` | `HTTP/1.1 404 Not Found` | Xray на сервере корректно обрабатывает легитимный TLS |
| **Сырой бинарный TCP-пакет** | Инжекция `"HELLO FROM WORK PC\n"` | **Долетел за 8 мс** | Обычные данные не фильтруются по портам |

## 3. Локализация точки отказа (Deep Packet Injection & Isolation)

Для исключения влияния виртуального интерфейса Wintun (`singbox-tun0`) и DNS-стека Windows был проведен «чистый эксперимент»:
1. На рабочем ПК запущен изолированный процесс `sing-box.exe` в режиме прокси (`inbounds: mixed` на порту `127.0.0.1:12407`) с боевым конфигом Reality.
2. Отправлен прямой HTTP-запрос через локальный порт:
   ```powershell
   curl.exe -i --max-time 10 -x http://127.0.0.1:12407 http://1.1.1.1/
   ```
3. **Результат в логах sing-box:**
   ```text
   INFO inbound/mixed[mixed-in]: inbound connection to 1.1.1.1:80
   INFO outbound/vless[proxy-out]: outbound connection to 1.1.1.1:80
   ERROR [15.9s] connection: open connection to 1.1.1.1:80 using outbound/vless[proxy-out]: context deadline exceeded
   ```
4. **Инжекция сырого ClientHello Reality:**
   Был захвачен эталонный 593-байтовый пакет ClientHello Reality с домашнего ПК и отправлен напрямую в сокет `89.124.94.246:443` и `89.124.94.246:2096` с рабочего ПК.
   * **Результат:** `NO RESPONSE (DROPPED BY DPI)`.
   * **Физика блокировки:** Корпоративный Next-Generation Firewall (UserGate / FortiGate) на шлюзе `192.168.12.200` выполняет глубокую инспекцию L7. В Reality аутентификация инкапсулируется в зашифрованные поля `SessionID` и `KeyShare`. Файрвол распознает высокую энтропию («Circumvention / Non-standard TLS») и **молча отбрасывает L7-пакет данных**, не разрывая TCP-сессию RST-пакетом.

## 4. Контекст пользователя и смена стратегии

Пользователь раскрыл свой контекст:
> *«Я здесь сисадмин бро, у меня доступ ко всему есть, я тут царь и бог... Я хочу довести Exilium Switch до ультимативного состояния, чтобы это была нереально крутая утилита, чтобы даже если бы я работу сменил, без проблем бы потом VPN мой там заработал например».*

Вместо локального добавления исключения на текущем шлюзе было принято решение **разработать ультимативную двухэшелонную архитектуру**, которая гарантированно пробивает любые корпоративные файрволы (UserGate, FortiGate, CheckPoint, Palo Alto) в любых организациях без вмешательства в чужие шлюзы.

## 5. Архитектурное решение: Enterprise Stealth

### Анализ сертификатов на VPS #1:
При исследовании сервера выяснилось, что на VPS #1 в `/root/cert/ip/fullchain.pem` уже находился официальный сертификат от **Let's Encrypt CA**, выданный непосредственно на IP-адрес `89.124.94.246`:
```text
Issuer: C = US, O = Let's Encrypt, CN = YE1
X509v3 Subject Alternative Name: IP Address:89.124.94.246
```
Это дало возможность поднять 100% легитимный HTTPS/WSS транспорт без необходимости покупки и привязки доменов!

### Схема двух эшелонов Exilium Switch:

```
                  ┌───────────────────────────────────────────────────────────┐
                  │                    Exilium Switch                         │
                  └─────────────┬───────────────────────────────┬─────────────┘
                                │                               │
                Режим «Дом / Игры»                       Режим «Офис»
                                │                               │
                   VLESS Reality (Порт 443)            VLESS WS TLS (Порт 2096)
                                │                               │
                 Маскировка под dl.google.com          Официальный Let's Encrypt IP
                   0 RTT, чистый сокет              RFC 6455 легитимный WebSocket
                                │                               │
                     [Домашние провайдеры / ТСПУ]      [Корпоративный NGFW / DPI]
                                │                               │
                                ▼                               ▼
                  ┌───────────────────────────────────────────────────────────┐
                  │                   VPS #1 (89.124.94.246)                  │
                  │   - Inbound 1: NL-Reality (443)                           │
                  │   - Inbound 2: Office-Stealth (2096)                      │
                  └───────────────────────────────────────────────────────────┘
```

## 6. Реализация на сервере (VPS #1)

1. **Освобождение порта 2096:**
   * Служебный порт подписок 3X-UI перенесен в SQLite `x-ui.db` с `2096` на `2095`.
   * Сняты временные NAT-правила iptables.
2. **Создание Inbound 2 (`Office-Stealth`):**
   * В таблицу `inbounds` добавлен инбаунд на порту `2096` с протоколом `vless`, транспортом `ws` (путь `/office-ws`) и сертификатом Let's Encrypt.
   * В таблицах `clients`, `client_inbounds` и `client_traffics` привязан клиент `Aviabaza-PC` (UUID `2d34c6bd-dbec-4f75-b723-c55fcd4e7eb9`).
   * Перезапущен сервис `x-ui`: Xray стал одновременно слушать `*:443` и `*:2096`.
3. **Безопасность исходного входа:**
   * Inbound `NL-Reality` (порт 443) остался нетронутым — домашний ПК и айфоны продолжили работать без малейших изменений.

## 9. Итоговая памятка по работе с 3X-UI

Для добавления новых пользователей в систему теперь используется следующее правило:

| Сценарий использования | Назначение в 3X-UI | Ссылка для клиента |
| :--- | :--- | :--- |
| **Домашний ПК, ноутбук, смартфон** | Inbound 1 (`NL-Reality`, порт 443) | `vless://<uuid>@89.124.94.246:443?security=reality&...#NL-Home` (активируется в режиме «Дом») |
| **Рабочий ПК в строгой корпоративной сети** | Inbound 2 (`Office-Stealth`, порт 2096) | `vless://<uuid>@89.124.94.246:2096?type=ws&security=tls&path=%2Foffice-ws&sni=89.124.94.246#Office-Stealth` (активируется в режиме «Офис») |
| **Универсальный клиент (и дома, и на работе)** | Клиент добавляется в **оба инбаунда** | Пользователь импортирует обе ссылки, а тумблер в приложении переключает режимы «Дом» / «Офис» на лету |
