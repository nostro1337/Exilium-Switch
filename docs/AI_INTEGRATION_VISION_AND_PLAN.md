## 1. Хронологическая сводка диалога и принятые решения

В ходе совместного проектирования автора (визионера) и главного инженера сформирована концепция персонального цифрового бастиона с интегрированным искусственным интеллектом.

| Шаг | Тема обсуждения | Принятое решение и архитектурный консенсус |
| :--- | :--- | :--- |
| **№1** | **Миссия и позиционирование** | Персональный защитный бастион для автора и семьи (никакой коммерции). Принцип «Zero-Anxiety UX» — полное снятие тревожности от логов и прозрачная демонстрация здоровья сети. |
| **№2** | **AI-провайдер и стоимость** | **Google AI Studio (Gemini 2.0 Flash)**. 100% бесплатный ключ, до 15 RPM, контекст 1M, задержка ответа < 1 сек. Себестоимость = 0$. |
| **№3** | **Сетевой инвариант ИИ** | Запросы к Gemini API отправляются **строго при активном VPN-туннеле** через европейский Egress. Это гарантирует отсутствие блокировок Google API со стороны провайдеров РФ. При выключенном VPN работает локальный эвристический аудит. |
| **№4** | **Zero-Waste стратегия кэширования** | Внедрение **Log Normalizer (Fingerprint Engine)**: замена динамических IP/портов на токены. Запрос в Gemini отправляется только 1 раз на новый уникальный шаблон. 99% карточек отдаются мгновенно из локального кэша (`ai_cache.json`). |
| **№5** | **Компоновка интерфейса (UI)** | **Вариант А (Sentinel Dashboard HUD):** Информативная 3-модульная нижняя панель (Маскировка ОС / Live HUD телеметрия / Полоса вердикта ИИ) с адаптивным раскрытием графика стабильности при изменении размера окна (`resize`). |
| **№6** | **Телеметрия в реальном времени** | Фоновый движок: быстрый пинг и джиттер (3–5 сек), канареечные проверки сервисов (30–60 сек), пассивный перехват сокетов sing-box в реальном времени. |
| **№7** | **Интерактивность логов** | Кликабельные строки `[WARN]` и `[ERR]` в консоли логов с открытием карточки объяснения и советом по действиям. |
| **№8** | **Онбординг ключа в UI** | В `SettingsModal` добавляется раздел `AI Sentinel` с кнопкой быстрого перехода в Google AI Studio (`1-Click`), проверкой связи и 3-шаговой инструкцией. |

## 2. Философия: «Золотой треугольник Exilium»

```
          ┌────────────────────────────────────────┐
          │         1. Облачный Сервер             │
          │   (VLESS-Reality / Hysteria2 / NL)     │
          │      Маскировка SNI, 0 логов           │
          └───────────────────┬────────────────────┘
                              │
                    Шифрованный TUN-канал
                     (Wintun + sing-box)
                              │
          ┌───────────────────┴────────────────────┐
          │         2. Клиентский Щит              │
          │        (Exilium Switch Core)           │
          │    DNS Loopback, Timezone, LFSVC       │
          └───────────────────┬────────────────────┘
                              │
                     Телеметрия + Egress
                              │
          ┌───────────────────┴────────────────────┐
          │      3. Когнитивный Интеллект          │
          │     (AI Sentinel / Gemini Flash)       │
          │    Анализ аномалий, вердикт, кэш       │
          └────────────────────────────────────────┘
```

1. **Сервер:** Надежный европейский узел с Reality/Hysteria2.
2. **Клиент:** [Exilium Switch](file:///e:/Code/ExiliumSwitch) на уровне Windows гарантирует изоляцию IPv6, сброс служб отслеживания координат (`lfsvc`), спуфинг часового пояса и предотвращение утечек DNS.
3. **ИИ (Когнитивный слой):** [AI Sentinel](file:///e:/Code/ExiliumSwitch/electron/services/) переводит системную телеметрию на человеческий язык, выявляет признаки цензурных атак и помогает мгновенно стабилизировать связь.

## 4. Спецификация подсистем

### 4.1. Движок отпечатков (Log Normalizer)

Преобразует высокодинамичные логи Go-рантайма `sing-box` в статические шаблоны для эффективного кэширования:

| Тип токена | Регулярное выражение | Подстановка |
| :--- | :--- | :--- |
| **IPv4 / IPv6** | `\b(?:\d{1,3}\.){3}\d{1,3}\b` | `<IP>` |
| **Порты TCP/UDP** | `:\d{2,5}\b` | `:<PORT>` |
| **Сессии / Время Go** | `\[\d+\s+\d+ms\]` | `[SESSION]` |
| **Домены / SNI** | `(?<=\s)([a-z0-9-]+\.)+[a-z]{2,}(?=\s|:)` | `<DOMAIN>` |

*Пример:*  
`[ERR] [918231 12ms] outbound/vless[proxy]: dial tcp 185.220.101.5:443: i/o timeout`  
⬇️ **Нормализация:**  
`outbound/vless: dial tcp <IP>:<PORT>: i/o timeout` (Хэш: `a7f8c9b1`)

### 4.2. Локальный кэш карточек (`userData/ai_cache.json`)

```json
{
  "templateId": "a7f8c9b1",
  "pattern": "outbound/vless: dial tcp <IP>:<PORT>: i/o timeout",
  "title": "Таймаут ответа целевого узла",
  "severity": "low",
  "isDangerous": false,
  "humanExplanation": "Целевой веб-сайт не ответил вовремя. Это нормальная ситуация для медленных или перегруженных ресурсов.",
  "recommendedAction": "Действий не требуется. Туннель и защита функционируют штатно.",
  "firstSeen": "2026-08-29T18:00:00Z",
  "occurrences": 14
}
```

### 4.3. Движок телеметрии (Telemetry Engine)

* **Health Score (0–100%):** Комплексный индекс качества соединения, вычисляемый по формуле:
  $$\text{HealthScore} = 100 - (\text{LossRate} \times 40) - (\text{JitterPenalty}) - (\text{DpiAnomalyPenalty})$$
* **Статусы DEFCON:**
  * `DEFCON 5 (95–100%)` — 🟢 Идеальный канал, аномалий нет.
  * `DEFCON 4 (85–94%)` — 🟢 Незначительные колебания задержки, канал стабилен.
  * `DEFCON 3 (70–84%)` — 🟡 Фиксация микро-потерь UDP или единичных сбросов RST.
  * `DEFCON 2 (50–69%)` — 🟠 Обнаружены признаки выборочной фильтрации SNI/портов.
  * `DEFCON 1 (< 50%)` — 🔴 Канал деградировал / блокировка узла.
