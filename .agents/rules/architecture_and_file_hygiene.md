# 3. Архитектурные границы и чистота репозитория (Architecture & File Hygiene)

Данный документ устанавливает обязательные требования к архитектуре и структуре файлов проекта **Exilium Switch**.

---

## 3.1. Строгая слоистая архитектура (Layered SoC)

Зависимости в проекте должны идти строго в одном направлении:

```
┌─────────────────────────────────────────────────────────┐
│                     shared/types                        │  (DTO, Контракты, IPC-каналы)
└───────────┬─────────────────────────────────┬───────────┘
            │                                 │
            ▼                                 ▼
┌──────────────────────┐          ┌───────────────────────┐
│   electron/utils     │          │      src/hooks        │  (React 18 Custom Hooks)
└───────────┬──────────┘          └───────────┬───────────┘
            ▼                                 ▼
┌──────────────────────┐          ┌───────────────────────┐
│  electron/services   │          │    src/components     │  (React UI Views)
└───────────┬──────────┘          └───────────────────────┘
            ▼
┌──────────────────────┐
│     electron/ipc     │  (IPC Handlers)
└───────────┬──────────┘
            ▼
┌──────────────────────┐
│    electron/core     │  (WindowManager, Tray, Main Lifecycle)
└──────────────────────┘
```

### Правила слоев:
- **Запрет прямого доступа к Node.js в UI:** React-компоненты и хуки никогда не используют `fs`, `child_process` или прямое обращение к Electron. Все вызовы идут через строго типизированный `window.electronAPI`.
- **Изоляция IPC:** IPC-обработчики в `electron/ipc/` отвечают только за валидацию входных параметров и делегирование в сервисы `electron/services/`.
- **Единый источник контрактов:** Все имена каналов объявляются только в `shared/ipc-channels.ts`, а структуры данных — в `shared/types/`.

---

## 3.2. Файловая гигиена (Repository Cleanliness Standards)

- **Корень проекта (`/`):** Должен содержать **только** стандартные конфигурационные файлы проекта (`package.json`, `tsconfig.json`, `vite.config.ts`, `vitest.config.ts`, `electron-builder.yml`, `tailwind.config.js`, `index.html`, `README.md`, `GEMINI.md`, `AGENTS.md`, `.gitignore`).
- **Запрет мусорных файлов в корне:** Запрещено оставлять в корне тестовые JSON (`temp_*.json`), дампы сетевых отчетов, инциденты или файлы логов.
- **Размещение файлов по категориям:**
  - `assets/icons/` — Иконки и графические ресурсы приложения.
  - `docs/` — Архитектурная документация, релизные регламенты.
  - `docs/reports/` — Отчеты аудита систем и хронологии решений.
  - `docs/incidents/` — Локальные дампы инцидентов и сетевых сбоев (игнорируются в `.gitignore`).
  - `Configs/samples/` — Примерные и шаблоны конфигураций.
  - `tests/` — Автоматизированные тесты Vitest.
