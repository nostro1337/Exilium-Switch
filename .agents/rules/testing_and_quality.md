# 1. Регламент тестирования и контроля качества (Testing & Quality Gate)

Данный документ устанавливает обязательные стандарты тестирования для ИИ-агентов при работе в репозитории **Exilium Switch**.

---

## 1.1. Правило непрерывного покрытия (Zero-Regression Policy)
- **Обязательность тестов:** При создании нового сервиса, утилиты, IPC-обработчика, хука или изменении существующей бизнес-логики **ОБЯЗАТЕЛЬНО** создаются новые модульные тесты в папке `tests/` или актуализируются существующие.
- **Никаких изменений без тестов:** Запрещено закрывать задачу без подтверждения работоспособности через автоматические тесты.

---

## 1.2. Порог покрытия (Coverage Threshold Gate)
- **Минимальный порог:** Общее покрытие строк (`% Lines`) по всему проекту **ОБЯЗАНО быть не менее 80%** (целевой эталон — 90-100%).
- **Покрытие функций (`% Funcs`):** Не менее **85%**.
- **Запрет деградации:** Ни один коммит или набор правок не должен снижать общий процент покрытия кодовой базы.

---

## 1.3. Требования к написанию тестов
- **Изоляция и Mocking:** Для модулей, использующих Electron (`app`, `BrowserWindow`, `Notification`, `shell`, `ipcMain`) и нативные бинарники Windows, применять изолированные Vitest-моки (`vi.mock('electron')`, `vi.mock('node:child_process')`).
- **Сетевые и системные таймауты:** Тесты, взаимодействующие с сетевыми адаптерами Windows PowerShell, WMI или `sing-box`, обязаны объявлять явный таймаут (например, `it('...', async () => {}, 20000)`).
- **Краевые случаи (Edge Cases):** Всегда тестировать:
  1. Ошибки парсинга поврежденных конфигов JSON / невалидных ссылок VLESS.
  2. Отмену пользователем диалоговых окон выбора файла (`canceled: true`).
  3. Поведение сервисов при отсутствии внешних бинарников (`sing-box.exe`).
  4. Идемпотентность повторных вызовов Failsafe-санации сети.

---

## 1.4. Обязательный пайплайн валидации (Definition of Done)
Перед отправкой отчета пользователю агент **ОБЯЗАН** выполнить:
1. `npm run test:coverage` — Все 100% тестов должны пройти успешно, а покрытие строк должно быть `>= 80%`.
2. `npm run build` (или `npx tsc --noEmit`) — 0 ошибок компиляции TypeScript.
