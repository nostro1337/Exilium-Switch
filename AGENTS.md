# Системные правила и регламент разработки (AGENTS.md)

Данный файл содержит обязательные системные инструкции для ИИ-агента при работе в репозитории **Exilium Switch**.

---

## 1. Контроль качества и тестирование (Testing & Quality Gate) — ОБЯЗАТЕЛЬНО
- **Непрерывное покрытие (Zero-Regression):** При любых изменениях, исправлениях или добавлении функциональности агент **ОБЯЗАН** писать новые тесты в `tests/` или актуализировать существующие.
- **Порог покрытия кодовой базы:** Общее покрытие строк (`% Lines`) обязано оставаться **>= 80%** (целевой уровень: 85–100%). Не допускается снижение покрытия.
- **Валидация перед сдачей задачи:**
  1. `npm run test:coverage` — 100% тестов пройдены, покрытие строк `>= 80%`.
  2. `npm run build` / `npx tsc --noEmit` — 0 ошибок сборки и типов.

---

## 2. Навигация по коду и архитектуре (Code Intelligence)
- **Приоритет CodeGraph:** При поиске функций, изучении логики и планировании правок **ВСЕГДА** в первую очередь использовать инструменты CodeGraph (`codegraph_explore`, `codegraph_callers`, `codegraph_callees`, `codegraph_node`). Запрещено спамить слепым поиском `grep_search` и открытием десятков файлов, если символ есть в AST-графе.
- **Проверка зоны влияния (Impact):** Перед изменением сигнатур, структур, интерфейсов или компонентов всегда выполнять `codegraph_impact <символ>`.
- **Синхронизация знаний (Graphify):** После внесения изменений в код запускать `python -m graphify update .`.

---

## 3. Сетевая безопасность и системная надежность (Network Safety)
- **Zero-Network-Leak Invariant:** Методы сброса сети (`restoreRegularNetwork()`, `flushDns()`, `runStartupSanitation()`) обязаны быть идемпотентными и гарантировать, что сетевые адаптеры Windows никогда не останутся с фиктивными DNS при сбоях.
- **Синхронизация через Mutex:** Все операции переключения VPN и режимов (`toggle`, `start`, `stop`, `setAppMode`) строго изолируются через `StateMachine.getInstance().withLock()`.
- **Защитный Interop:** Все обращения к окнам через Electron API обязаны проверять `if (mainWindow && !mainWindow.isDestroyed())`.

---

## 4. Архитектура и файловая гигиена (Architecture & Hygiene)
- **Слоистая модель:** Зависимости идут строго: `shared/` ➔ `electron/utils/` ➔ `electron/services/` ➔ `electron/ipc/` ➔ `electron/core/` ➔ `src/hooks/` ➔ `src/components/`.
- **Изоляция UI:** React-компоненты никогда не используют Node.js API напрямую; вызовы идут только через типизированный мост `window.electronAPI`.
- **Чистота корня репозитория:** В корне проекта разрешены только стандартные конфигурационные файлы. Все дампы инцидентов направляются в `docs/incidents/`, отчеты в `docs/reports/`, иконки в `assets/icons/`.

---

## 5. Форматирование ответов и визуализация
- **Таблицы в чате:** Все таблицы, списки параметров, сравнения и структурированные данные в сообщениях чата необходимо оформлять исключительно через нативный Markdown (`| колонка | колонка |`).
- **Mermaid-диаграммы:** Запрещено отправлять Mermaid-код напрямую в текстовые сообщения чата. Использовать Mermaid только при создании графических схем/диаграмм внутри **артефактов** (`.md` документов).
- **Кликабельные ссылки:** Обязательно оформлять кликабельные ссылки на файлы и символы в формате GitHub Markdown с протоколом `file://` (например, `[main.ts](file:///e:/Code/ExiliumSwitch/electron/main.ts)`).
