# Системные правила и регламент разработки (GEMINI.md)

Данный файл содержит обязательные системные инструкции для ИИ-агента при работе в репозитории **Exilium Switch**.

---

## 1. Навигация по коду и архитектуре (Code Intelligence)

В проекте настроена двухуровневая система кодового интеллекта (**CodeGraph** + **Graphify**). Агент обязан строго следовать иерархии инструментов:

### А. Микро-уровень: Работа с кодом (CodeGraph)
- **Приоритет CodeGraph:** При поиске функций, изучении логики и планировании правок **ВСЕГДА** в первую очередь использовать инструменты CodeGraph (`codegraph_explore`, `codegraph_callers`, `codegraph_callees`, `codegraph_node`). Запрещено спамить слепым поиском `grep_search` и открытием десятков файлов, если символ есть в AST-графе.
- **Обязательная проверка зоны влияния (Impact):** Перед изменением сигнатур, структур, интерфейсов или компонентов всегда выполнять `codegraph_impact <символ>`, чтобы выявить все зависимые файлы до внесения правок.

### Б. Макро-уровень: Архитектура и базы знаний (Graphify)
- **Анализ архитектуры:** При проектировании крупных подсистем, анализе ТЗ/документации или онбординге использовать граф знаний в `graphify-out/` (`graph.json`, `GRAPH_REPORT.md`, `wiki/`).
- **Синхронизация:** После внесения изменений в код запускать `graphify update .` для поддержания архитектурного графа в актуальном состоянии.

## 2. Форматирование ответов и визуализация

- **Таблицы в чате:** Все таблицы, списки параметров, сравнения и структурированные данные в сообщениях чата необходимо оформлять исключительно через нативный Markdown (`| колонка | колонка |`).
- **Mermaid-диаграммы:** Запрещено отправлять Mermaid-код напрямую в текстовые сообщения чата. Использовать Mermaid только при создании графических схем/диаграмм внутри **артефактов** (`.md` документов).
- **Кликабельные ссылки:** Обязательно оформлять кликабельные ссылки на файлы и символы в формате GitHub Markdown с протоколом `file://` (например, `[main.ts](file:///e:/Code/ExiliumSwitch/electron/main.ts)`).

---

## 3. Регламент масштабного рефакторинга (Planning Mode)

При любых крупных изменениях, добавлении систем или генеральном рефакторинге:
1. **Research:** Изучить существующие связи через `codegraph_explore` и `Graphify`.
2. **Plan:** Сформировать подробный `implementation_plan.md` с послойной структурой и получить одобрение пользователя перед внесением правок.
3. **Execute:** Выполнять правки по цепочке зависимостей «снизу вверх» (Types ➔ Utils ➔ Services ➔ UI).
4. **Verify:** Проверять сборку и типы через `npm run build` / `tsc --noEmit`.
